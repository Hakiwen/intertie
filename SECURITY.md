# Security

## Reporting a vulnerability

Please report privately, **not** in a public issue. Use **GitHub private vulnerability
reporting**: <https://github.com/Hakiwen/intertie/security/advisories/new> (Security tab,
then "Report a vulnerability"). Include affected versions, a reproduction, and the
impact.

You'll get an acknowledgement. Fixes are released as patch versions, and the advisory
credits you unless you ask otherwise. The same applies to the registry
(`Hakiwen/intertie-registry`) and the protocol text. A flaw in the *protocol* is as
welcome as a flaw in the code.

Supported versions: the latest release.

## Verifying a release

Every downloadable artifact of a release comes with SBOMs and attestations, all produced by
this repository's `release` workflow:

- the five package tarballs, `intertie-<pkg>-<ver>.tgz`;
- the source archive, `intertie-<ver>-src.tar.gz`.

For each artifact:

- **SBOMs** in CycloneDX 1.5 and SPDX 2.3, generated from `package-lock.json` by
  `npm sbom` (never written by hand), and scanned with OSV-Scanner before release.
- **SLSA build provenance**, signed keylessly with Sigstore from GitHub Actions OIDC. It
  names the repository, workflow, commit and runner.
- **An SBOM attestation per format**, which binds each SBOM to the artifact's SHA-256.

You need the GitHub CLI (`gh` ≥ 2.49):

```sh
gh release download v0.2.0 --repo Hakiwen/intertie
sha256sum -c SHA256SUMS

# Provenance: built by Hakiwen/intertie's release workflow from a tagged commit.
gh attestation verify intertie-core-0.2.0.tgz --owner Hakiwen

# The SBOMs are attested for this exact file.
gh attestation verify intertie-core-0.2.0.tgz --owner Hakiwen --predicate-type https://cyclonedx.org/bom
gh attestation verify intertie-core-0.2.0.tgz --owner Hakiwen --predicate-type https://spdx.dev/Document/v2.3
```

To verify offline, pass `--bundle <file>.sigstore.jsonl` (attached to every release).
Pinning the workflow is stricter:
`--signer-workflow Hakiwen/intertie/.github/workflows/release.yml`.

GitHub's automatic "Source code (zip / tar.gz)" downloads are generated by GitHub and
cannot be attested. Use `intertie-<ver>-src.tar.gz` instead.

When the packages are published to npm, they will be published with `--provenance`, and
`npm audit signatures` will verify them.

## Supply chain

- **Runtime dependencies: none.** The reference implementation uses only Node built-ins
  (`node:crypto`, `node:sqlite`, `node:http`). Each package's runtime SBOM lists only
  `@intertie/*`.
- **Dev and build dependencies:** TypeScript, `@types/node`, and Ajv for schema tests.
  The workspace SBOM lists them all.
- **CI:** every GitHub Action is pinned by commit SHA. Dependabot watches npm and the
  Actions. OSV-Scanner runs over the SBOMs on every push and weekly. Secret scanning with
  push protection is on.
- **Assurance:** the conformance runner's `security` level (an adversarial suite), a TLA+
  model checked with TLC in CI (`spec/model/`), and signature test vectors cross-checked
  against Go's standard library.
